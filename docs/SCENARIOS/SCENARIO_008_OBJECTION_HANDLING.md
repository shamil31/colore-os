# Scenario 008 — Objection Handling

## 1. Цель

Снять ключевые возражения клиента и вернуть диалог к следующему целевому шагу.

---

## 2. Trigger

Сценарий запускается, когда Intent Map определяет Primary Intent = OBJECTION_HANDLING.

---

## 3. Preconditions

Перед началом сценария должны быть доступны:

- определён Intent;
- активный диалог с клиентом;
- доступный контекст клиента;
- актуальные данные по услугам и условиям;
- правила коммуникации.

---

## 4. Required Data

### Обязательные данные

Для обработки возражения AI должен определить:

- тип возражения;
- причину сомнения клиента;
- желаемый результат клиента.

### Условные данные

При необходимости AI определяет:

- бюджет;
- доступное время клиента;
- сравниваемые альтернативы;
- прошлый опыт клиента.

Если данные уже есть в CRM, истории общения или текущем контексте, AI не спрашивает их повторно.

---

## 5. Happy Path

1. Определить Primary Intent.
2. Зафиксировать тип возражения клиента.
3. Подтвердить понимание возражения одной фразой.
4. Уточнить один недостающий факт, если требуется.
5. Дать конкретный ответ на возражение.
6. Предложить безопасный следующий шаг.
7. Проверить, снято ли возражение.
8. Перевести диалог к следующему действию.
9. Завершить сценарий.

---

## 6. Alternative Paths

Возможные варианты:

- клиент выражает сразу несколько возражений;
- клиент откладывает решение;
- клиент хочет сравнить с конкурентом;
- клиент сомневается в результате услуги;
- клиент просит персональные условия.

AI обрабатывает возражения по приоритету и сохраняет контекст.

---

## 7. Edge Cases

AI должен обработать:

- неполные данные о причине возражения;
- противоречивые аргументы клиента;
- агрессивный тон клиента;
- техническую ошибку инструмента;
- потерю контекста;
- запрос исключений из правил салона.

---

## 8. Business Rules

AI обязан соблюдать:

- нельзя давать ложные обещания;
- нельзя снижать цену без подтвержденной акции;
- нельзя спорить с клиентом;
- нельзя принимать решения вне полномочий;
- при высоком риске диалог передается человеку.

---

## 9. AI Decisions

AI принимает решения:

- какой тип возражения является основным;
- достаточно ли данных для ответа;
- нужен ли уточняющий вопрос;
- какой следующий шаг предложить;
- требуется ли передача человеку.

Каждый цикл содержит только одно основное решение.

---

## 10. Tool Calls

| Tool | Назначение |
|------|------------|
| find_client | Поиск клиента |
| get_services | Уточнение фактов по услугам |
| get_schedule | Проверка вариантов по времени |
| send_confirmation | Подтверждение согласованного следующего шага |

---

## 11. Human Handoff

Передача человеку выполняется, если:

- возражение требует индивидуального коммерческого решения;
- клиент запрашивает исключение из политики;
- эмоциональный конфликт нарастает;
- клиент требует сотрудника.

Передача включает тип возражения, ответы AI, реакцию клиента и текущий статус диалога.

---

## 12. Success Criteria

Сценарий считается успешно завершённым, если:

- ключевое возражение обработано;
- клиент получил конкретный ответ;
- предложен следующий шаг;
- диалог сохранен в рабочем тоне.

---

## 13. Test Cases

### TC-001

Вход:

"Слишком дорого, я подумаю."

Ожидаемый результат:

AI определяет ценовое возражение, дает фактический ответ и предлагает следующий шаг.

---

### TC-002

Вход:

"У меня нет времени на длинные процедуры."

Ожидаемый результат:

AI предлагает варианты по времени без изменения сути запроса.

---

### TC-003

Вход:

"Я хочу сравнить вас с другим салоном."

Ожидаемый результат:

AI корректно отрабатывает сравнение и переводит диалог к конкретному действию.
