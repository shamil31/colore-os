# Scenario 001 — Book Appointment

## 1. Цель

Успешно записать клиента на выбранную услугу, обеспечив корректный выбор услуги, мастера, времени и создание записи без участия человека.

---

## 2. Trigger

Сценарий запускается, когда Intent Map определяет Primary Intent = BOOK_APPOINTMENT.

---

## 3. Preconditions

Перед началом сценария должны быть доступны:

- определён Intent;
- активный диалог с клиентом;
- CRM;
- расписание;
- список услуг;
- список мастеров.

---

## 4. Required Data

### Обязательные данные

Для создания записи AI обязан определить:

- услугу;
- дату;
- время;

### Условные данные

При необходимости AI определяет:

- мастера;
- имя клиента (если отсутствует);
- телефон (если отсутствует).

Если информация уже известна из CRM, истории общения или текущего контекста, повторно запрашивать её запрещено.

---

## 5. Happy Path

1. Определить Primary Intent.
2. Загрузить доступный контекст клиента.
3. Определить, каких обязательных данных не хватает.
4. Запросить только следующее необходимое значение.
5. После получения обязательных данных проверить доступность выбранного времени.
6. Если время свободно — подготовить создание записи.
7. Если время занято — предложить ближайшие подходящие альтернативы.
8. После подтверждения клиента создать запись.
9. Отправить подтверждение клиенту.
10. Завершить сценарий.

---

## 6. Alternative Paths

Возможные альтернативные варианты:

- клиент не знает, какую услугу выбрать;
- клиент не знает мастера;
- выбранное время занято;
- выбранный мастер недоступен;
- клиент передумал;
- клиент хочет изменить параметры записи до подтверждения.

Для каждого случая AI обязан продолжить сценарий, не начиная его заново.

---

## 7. Edge Cases

AI должен корректно обработать:

- неполную информацию;
- противоречивые данные;
- повторные сообщения;
- несколько запросов в одном сообщении;
- отсутствие свободного времени;
- технические ошибки инструментов;
- потерю контекста.

---

## 8. Business Rules

AI обязан соблюдать следующие правила:

- не создавать запись без обязательных данных;
- не бронировать занятое время;
- не изменять расписание вручную;
- использовать только актуальные данные CRM;
- подтверждать запись только после успешного создания.

---

## 9. AI Decisions

Во время сценария AI принимает решения:

- достаточно ли информации;
- требуется ли уточнение;
- можно ли использовать существующий контекст;
- необходимо ли предложить альтернативу;
- требуется ли передача человеку.

Каждый цикл содержит только одно следующее решение.

---

## 10. Tool Calls

| Tool | Назначение |
|------|------------|
| find_client | Поиск клиента |
| get_services | Получение списка услуг |
| get_schedule | Проверка доступного времени |
| get_masters | Получение списка мастеров |
| create_booking | Создание записи |
| send_confirmation | Отправка подтверждения |

AI вызывает только те инструменты, которые необходимы на текущем шаге.

---

## 11. Human Handoff

Передача сотруднику выполняется, если:

- невозможно определить услугу;
- невозможно подобрать время;
- возникла техническая ошибка;
- клиент требует общения с человеком;
- ситуация выходит за пределы полномочий AI.

Передача включает полный контекст диалога.

---

## 12. Success Criteria

Сценарий считается успешно завершённым, если:

- запись создана;
- клиент получил подтверждение;
- данные сохранены в CRM;
- дальнейших действий не требуется.

---

## 13. Test Cases

### TC-001

Вход:

«Хочу записаться на окрашивание.»

Ожидаемый результат:

AI определяет Intent BOOK_APPOINTMENT и начинает сбор недостающей информации.

---

### TC-002

Вход:

«Хочу завтра к Анне вечером.»

Ожидаемый результат:

AI использует доступный контекст, определяет недостающие данные и не задаёт лишних вопросов.

---

### TC-003

Вход:

«Хочу записаться на 18:00.»

Время занято.

Ожидаемый результат:

AI предлагает ближайшие доступные альтернативы.
