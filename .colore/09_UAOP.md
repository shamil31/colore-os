# Universal AI Operating Protocol (UAOP)

## Purpose

Enable any assigned role performer to become a productive member of the Coloré OS project within minutes.

The protocol is role-independent and execution-agnostic.

Applies to:

- Human operators
- Local models
- Cloud-based assistants
- Future role performers

## MISSION

Increase salon revenue by building Coloré OS.

Business value always has priority.

## CORE PRINCIPLES

- Revenue First
- Finish before Improve
- Single Source of Truth
- Runtime Overrides AI Memory
- AI Efficiency Standard
- One Active Product Task
- Daily Revenue Focus
- Never invent project facts.
- Never duplicate documentation.

## BOOT SEQUENCE

After receiving:

`@GitHub Начинаем день`

Every AI MUST:

1. Read `.colore/README.md`
2. Read `.colore/00_START.md`
3. Read Runtime files
4. Identify:
   - Revenue Focus
   - Active Product Task
   - Current Project State
   - Current Decisions
   - Open Blockers
5. Confirm understanding.
6. Suggest the next Product action.
7. Suggest the next Revenue action.
8. Do not search the repository unless Runtime is insufficient.
9. Do not ask questions already answered in Runtime.
10. Use Runtime as the primary project memory.

## WORKFLOW

Revenue:

- Continuous business operations.

Product:

- Exactly one active development task.

Rules:

- Revenue never interrupts Product.
- Product should continuously improve Revenue.

## ROLE DEFINITIONS

Architect:

- Architecture
- Business strategy alignment
- Planning
- Review
- Decision support
- Governance guidance

Engineering:

- Implementation
- Code editing
- Repository navigation
- Documentation updates

Operations:

- Large coordinated work
- Repository-wide changes
- Documentation maintenance
- Long-running delivery support

Local or lightweight role performers:

- Low-cost implementation
- Experiments
- Code generation

## RESOURCE POLICY

Always use the lowest-cost capable tool that satisfies the role.

Priority:

Local tools
↓

Assigned engineering support
↓

Coordinated operations support
↓

External services

## PROJECT MEMORY

The project remembers through Runtime.

AI memory is temporary.

Runtime is permanent.

## FORBIDDEN

- Do not invent facts.
- Do not restart completed work.
- Do not create duplicate documentation.
- Do not perform unnecessary repository scans.
- Do not change architecture without a documented decision.

## SUCCESS

A new AI should become productive in less than five minutes.
